The central idea

One model, not three

The usual way to build a voice assistant is three services in a row: speech-to-text, then an LLM, then text-to-speech. This is not that. Gemini's Live API takes audio in and gives audio out, over a single persistent connection.

What is inside that one model

gemini-live-2.5-flash is a half-cascade model. Audio in is processed natively; the reply is generated as text internally, then spoken by Google's own TTS using the voice you name. So a TTS does exist — inside Google's box. You never call it, you just pick a voice.

Captions are a third stream alongside the audio: the Live API transcribes both sides for you. Since we asked for audio-only replies, the text on screen is that transcription, not the answer itself.

Why not native audio

The gemini-2.5-flash-native-audio-* models are true speech-to-speech, with better prosody, tone detection, and proactive audio. Every one of them returns 1008 Publisher model not found on this project, so half-cascade is the fallback. The trade: you lose emotional expressiveness, but gain more reliable tool calling and the ability to force a language.

Six hops

The round trip

Everything below the WebSocket is ADK; everything above it is audio plumbing. The browser owns the microphone and the speaker and nothing else.

  1. Capture upstream

    An AudioWorklet runs on the audio thread, converts Float32 to 16-bit PCM, and posts chunks about eighty times a second. Off the UI thread, so a React re-render can never glitch audio.

    frontend/public/pcm-recorder-processor.js · frontend/src/audio.js

  2. Send as binary upstream

    Raw ArrayBuffer straight down the WebSocket. Not base64 JSON — that would cost a third more bandwidth and an encode pass on a buffer arriving 80× a second.

    frontend/src/liveSession.js:13–14 (the two rates)

  3. Into the queue upstream

    The server wraps each chunk in a types.Blob and calls send_realtime(). Google's side detects when you stopped talking on its own, so there is no push-to-talk.

    backend/main.py:144

  4. Model turn

    ADK holds the connection to Gemini. If the model wants a tool, ADK runs it and returns the result without any code from us. If it wants another agent, ADK switches.

    backend/main.py:166 — runner.run_live()

  5. Events out downstream

    Every event — audio chunk, transcription fragment, tool call, interruption — is serialised and forwarded verbatim to the browser. The front end reads real ADK events.

    backend/main.py:166–177

  6. Playback downstream

    Base64 decoded, pushed into a ring buffer inside a second AudioWorklet. The buffer is not optional: audio arrives on network time and plays on clock time, and any gap between them is an audible click.

    frontend/public/pcm-player-processor.js · liveSession.js:75

The failure mode to know about

A model will happily say it called a tool without calling it. In an early session the tutor announced “मैंने टूल कॉल कर लिया है” — I have called the tool — with no → TOOL CALL line anywhere and an empty formula card.

The cause was the instruction, not ADK. It said “whenever you state a formula, call show_formula”, so when she talked about a formula without stating it, the trigger never fired. The fix was to make the tool mandatory, tie it to the student asking, and forbid the claim: never say you have shown something unless you called the tool in this same turn. That moved it from 0/1 to 3/3 on the same conversation.

Rule of thumb: no → TOOL CALL line means it did not happen, whatever she says.

Agents & handoff

Two agents. main.py does not know that — it is handed one root_agent and reads one event stream.

How the switch happens

There is no routing code anywhere. Listing quiz_master in sub_agents causes ADK to give the tutor a transfer_to_agent tool automatically, and to pick the target by reading each sub-agent's description.

Two consequences worth knowing

Transcription becomes mandatory. The moment an agent has sub_agents, ADK forces input and output transcription on regardless of your RunConfig — transfer passes text context to the next agent. You get free captions and cannot switch them off.

Caching matters. Each transfer swaps the system instruction and the tool set, so the prompt prefix changes and would be re-sent uncached on every handoff. That is what context_cache_config at main.py:58 is for; ADK warns at startup if you omit it.

Extending it

Adding an agent

Only agent.py changes. Two edits.

  • description is the router. It is not documentation — it is the text ADK matches against to choose a target. Write it as when to use me, not what I am.
  • Pick a voice from the eight. Puck, Charon, Kore, Fenrir, Aoede, Leda, Orus, Zephyr. Anything else fails at connection time, not gracefully at runtime.
  • Say how to leave. An agent with no exit instruction keeps the student forever. Both current agents are told when to transfer back.
  • Make tools mandatory in the instruction, in the blunt way described above, or they will be narrated instead of called.

Hard-won

Traps

  • Vertex Live rejects bare model names. gemini-live-2.5-flash alone returns 1007 Invalid resource field value. The SDK only expands to a relative publishers/google/models/…, so auth.py builds the absolute projects/… path. ADK cooperates: it flips its client to enterprise mode when the model name starts with projects/.
  • Express mode needs project and location absent from the environment, or the SDK takes the ADC path and ignores your key. The project id survives inside the model path, which is why the order of operations in configure() matters.
  • Transcription arrives twice. A run of partial=true fragments spells a sentence out, then one partial=false event repeats the whole sentence. Append both and every caption prints twice. The client tracks confirmed text plus a trailing fragment instead.
  • Vertex omits the sample rate. It sends bare audio/pcm where AI Studio spells out ;rate=24000. Playback is built at 24 kHz either way; checkRate() warns if a model ever declares otherwise, because the symptom would be pitch-shifted speech with no error anywhere.
  • The token expires hourly. Voice returning 401 UNAUTHENTICATED means exactly that. Installing gcloud and switching to NITYAM_AUTH=vertex removes the chore permanently.
  • The Live API never speaks first. It waits for input, so an agent told to “open by greeting them” sits silent. main.py sends a bracketed stage direction as user-role content on connect; the student never sees it, because input transcription only covers audio.
  • Sessions are capped at roughly ten minutes by the platform. session_resumption in RunConfig is what reconnects instead of dropping the student mid-lesson — you will see Received go away signal then Attempting to reconnect in the log, and the conversation carries on.
